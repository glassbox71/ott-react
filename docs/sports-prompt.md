# 학생용 스포츠 페이지 제작 프롬프트

아래 문장을 복사해 사용하세요. 저장소·종목·배포 주소를 본인 프로젝트에 맞게 바꾸세요. 같은 프롬프트라도 기존 코드, API 설정, 실행 환경에 따라 결과가 달라지므로 검증 결과까지 확인해야 합니다.

```text
이 저장소의 기존 앱에 스포츠 메뉴와 실제 라이브 시청·채팅 기능을 구현해 주세요.

수정 대상: glassbox71/ott-react
비교 대상: glassbox71/wavve-test의 src/api/sports.ts, src/pages/Sports.tsx,
          src/components/SportsChat.tsx, docs/sports.md
종목: 축구 (야구로 만들 때는 이 줄과 검색어를 야구/baseball로 바꾸세요)
배포 대상: 이 저장소에 연결된 기존 배포 프로젝트

1. 먼저 저장소의 AGENTS.md, 라우터, 헤더, 인증, Firebase 설정,
   환경 변수 이름, 배포 설정을 확인하세요. 비교 대상은 읽기만 하고
   수정·커밋·푸시는 수정 대상 저장소에서만 하세요.

2. 메인 메뉴 마지막에 '스포츠'를 추가하고 /sports 경로를 연결하세요.
   PC와 모바일에서 플레이어, 경기 목록, 채팅을 편하게 사용할 수 있게 하세요.

3. 실제 데이터 소스를 조사하고 확인한 출처를 설명하세요.
   YouTube Data API v3 search.list에서 type=video, eventType=live,
   videoEmbeddable=true, 축구/soccer 검색어, order=viewCount로 검색한 뒤
   videos.list에서 공개 여부, 외부 재생 허용, 실제 방송 시작 여부,
   종료 여부를 다시 확인하세요. 동시 시청자 수 내림차순 TOP 5와
   전체 라이브 목록을 보여 주세요. FIFA 공식 채널만 보는 필터도 만드세요.
   제목에 명확한 게임·시뮬레이션·해설·관계없는 콘텐츠는 제외하되,
   검색 메타데이터만으로 모든 영상의 경기 내용·중계 권한을 보증하지 마세요.

4. 예시 카드, 하이라이트, 채널 주소만 넣은 플레이어를 실제 라이브
   경기라고 표시하지 마세요. 재생 가능한 방송이 5개 이상 있으면
   최소 5개를 보여 주고, 적으면 실제 개수를 설명하세요.
   조회 중·키 누락·권한 오류·할당량 초과·검색 결과 없음·방송 종료를
   구분하세요. 가짜 LIVE 표시나 가짜 시청자 수를 만들지 마세요.

5. 방송 선택 시 해당 video ID의 YouTube 플레이어를 열고, 같은 방송을
   보는 접속자끼리 Firebase Firestore onSnapshot으로 채팅하게 하세요.
   기존 로그인을 재사용하고 방송별 채팅을 분리하세요. 메시지 길이 제한,
   전송 중 상태, 실패 안내, 구독 해제와 안전한 텍스트 렌더링을 포함하세요.
   Firestore 규칙은 기존 규칙을 보존하면서 인증 사용자와 본인 UID를 검증하게
   준비하세요. 권한이 있으면 규칙을 배포하고 실제 두 사용자로 검증하세요.

6. 기존에 설정된 VITE_YOUTUBE_API_KEY와 VITE_FIREBASE_*를 우선 확인하세요.
   변수 이름과 설정 여부만 출력하고 값을 대화·로그·Git에 노출하지 마세요.
   API 키를 새로 지어내거나 다른 Firebase 프로젝트의 키를 무단 복사하지 마세요.
   키가 없으면 필요한 설정과 정확한 차단 원인을 설명하고 독립적인 작업은
   계속하세요. 키는 배포 플랫폼의 환경 변수에 안전하게 설정해야 합니다.

7. 검색은 5분 캐시와 주기적 갱신으로 할당량 사용을 줄이세요.
   대규모 운영에는 서버 캐시가 필요하다는 점을 문서화하세요.
   브라우저용 키에는 HTTP referrer와 API 사용 제한을 권장하세요.

8. 빌드·변경 코드 린트·의미 있는 테스트를 실행하세요. 브라우저에서
   라이브 목록, 인기 순위, 영상 선택, 모바일 화면, 오류 상태를 확인하세요.
   실제 외부 조회·실제 영상 재생·모의 데이터 테스트·다중 사용자 채팅 검증을
   구분해 보고하세요. 테스트 통과를 외부 생중계 재생 성공으로 표현하지 마세요.

9. GitHub 반영과 기존 사이트 배포까지 진행하세요. 기존 배포 연결과 환경 변수를
   확인하고 /sports 직접 접속·새로고침도 동작하게 설정하세요.
   수정 대상 main 반영, 배포 성공, 운영 사이트 접속 검증을 각각 확인하세요.
   배포 권한 또는 설정이 없으면 코드는 완성·검증하고 남은 정확한 조치를 설명하세요.
   확인하지 않은 배포를 완료했다고 말하지 마세요.

마지막으로 바뀐 기능, 출처, 통과·실패·미검증 항목, 커밋, 실제 배포 상태를
간단히 보고하고, 재사용할 설정·실행·검증 방법을 문서로 남겨 주세요.
```

## 이번 비교에서 확인한 차이

- `wavve-test`는 YouTube의 공개 야구 라이브 전체 검색과 동시 시청자 수 순위를 사용합니다. FIFA 한 채널에 제한하지 않습니다.
- 이전 `ott-react` 구현은 FIFA 한 채널과 미리보기 위주였고, 공개 라이브 전체 검색과 TOP 5가 빠져 있었습니다.
- 비교 저장소의 기존 YouTube 설정으로 실제 API 조회가 가능함을 확인했습니다. FIFA 검색 결과가 비어 있는 것과 전체 축구 라이브가 없는 것은 다릅니다.
- 참고 저장소의 키 값을 새 저장소에 커밋하지 않았습니다. 배포 프로젝트의 환경 변수는 프로젝트마다 별도로 확인해야 합니다.
